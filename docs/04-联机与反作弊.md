# 联机设计：加入时空

> 「你不是登录一个服务器。你是把意识接进一条正在关闭的裂缝。」
>
> —— 阿刻，第一次连接时空时

---

## 一、一句话设计

**服务器只负责让人找到彼此、把话传到彼此耳朵里；对局本身活在每个玩家的内存里。**

- 入口叫「加入时空」。
- 房间叫「时空」或「裂谷」。
- 房主叫「执事」，不是管理员。
- 所有人以平民身份、同一 tick、同一份资源开局。
- 联机对局不写本地文件、不上传存档、不落数据库。
- 关房即焚，进程重启即全部消失。

---

## 二、设计原则

### 1. 房间制，不做 MMO

- 一局 1–8 人，推荐 4 人。
- 4 位时空码，支持公开列表和私密房间。
- 没有账号、没有好友、没有跨局关系。
- 退出房间，这局就和你无关。

### 2. 人人可当房主

- 任何人都能创建房间。
- 创建者是「初始执事」，不是老板。
- 开局前，任何人都可以申请执事，或由当前执事转让。
- 执事掉线，3 秒内自动选举新执事。
- 执事没有改资源、改战斗结果的权限。

### 3. 统一平民开局

所有人加入时：

- 12 人口，全部未分配。
- 1 座首都居住舱。
- 1 级电站、1 级矿场、1 级农场。
- 60 能源、90 矿物、40 食物、30 合金。
- 0 科研、0 影响力。
- 10 舰队。

没有隐藏加成，没有「房主礼包」，没有「先加入优势」。

### 4. 不落盘

- 联机对局数据只存在客户端内存。
- 服务器只保留房间元数据、成员列表、时钟和转发队列。
- 服务器不写存档、不写数据库、不写对局日志到磁盘。
- 服务器进程退出，所有房间立即消失。

### 5. 公平优先于绝对防作弊

纯客户端内存 + 帧同步可以防住：

- 改存档。
- 事后改分。
- 单方面改资源。
- 房主一言堂。

它防不住：

- 多个作弊者合谋。
- 修改客户端显示（只能骗自己）。
- 极端情况下的内存注入。

所以：

- 休闲房间靠「状态哈希互验 + 社交信誉」。
- 竞技/排名房间额外开「公证模式」，详见第九节。
- 不承诺「绝对无法作弊」，只承诺「作弊会被发现，且不能单方面改别人的游戏」。

## 三、角色与术语

| 术语 | 含义 |
| --- | --- |
| 加入时空 | 联机入口；创建或加入房间 |
| 时空 | 一个房间；也指这一局游戏 |
| 裂谷 | 房间的叙事称呼 |
| 时空码 | 4 位房间码 |
| 执事 | 房主；消息中转的负责人，不是管理员 |
| 成员 | 房间内的玩家 |
| 观战者 | 不参与对局、只能看和聊天的玩家 |
| 平民 | 所有玩家的统一开局身份 |
| tick | 逻辑帧；默认 2 Hz |
| 帧同步 | 所有客户端按同一 tick 执行同一批指令 |
| 状态哈希 | 对当前游戏状态计算的指纹 |
| 失真 | 某客户端状态与多数人不一致 |
| 公证模式 | 服务器在内存中跑一份只读校验模拟，不落盘 |
| 托管 | 玩家离线后由 AI 按预设方针运行 |
| 重连 | 掉线后带快照回到同一局 |

## 四、架构总览

> **现状说明（重要）**
>
> 当前原型为了先跑通房间，把每名玩家的 `GameState` 放在服务端内存里，通过 `/api/room/state` 下发。
> 这满足了「不落盘」，但**不满足**「对局数据只存客户端内存」。
>
> 本文档描述的是**目标架构**：
> M0 可以继续用服务端内存态过渡，先保证能玩；
> M1 起迁移到客户端帧同步 + 状态哈希；
> 迁移完成前，不要对外宣称已经实现「客户端内存态反作弊」。

```
┌─────────────┐        ┌──────────────────┐        ┌─────────────┐
│  玩家 A     │        │   加入时空服务器   │        │  玩家 B     │
│  客户端     │◄──────►│  房间注册 / 转发   │◄──────►│  客户端     │
│  内存状态   │        │  时钟 / 成员管理   │        │  内存状态   │
└─────────────┘        │  不存对局数据      │        └─────────────┘
                       └──────────────────┘
                                ▲
                                │
                       ┌────────┴────────┐
                       │  玩家 C / 观战者  │
                       └─────────────────┘
```

### 服务器职责

| 做 | 不做 |
| --- | --- |
| 创建 / 加入 / 离开房间 | 不模拟游戏 |
| 维护成员列表和在线状态 | 不保存游戏状态 |
| 生成时空码和随机种子 | 不写存档 |
| 转发指令、聊天、哈希 | 不决定战斗结果 |
| 提供共享时钟 tick | 不做账号系统 |
| 执行暂停 / 开始 / 踢人投票 | 不做持久排行榜 |
| 检测消息频率和大小 | 不做反作弊驱动 |

### 为什么房主不是网络主机

「执事」是**逻辑房主**，不是网络主机。

- 所有消息都经过「加入时空」服务器转发。
- 任何人当执事，都不需要公网 IP、端口映射、NAT 穿透。
- 服务器挂了，房间就没了；但单个玩家掉线不会影响别人。
- 执事迁移只是换一个「会话协调人」，不是把游戏状态搬过去。

这让「所有人都可以当房主」变成一件不需要技术门槛的事。

## 五、房间生命周期

### 状态机

```
创建 ──→ 等待 ──→ 倒计时 ──→ 对局中 ──→ 暂停 ──→ 结算 ──→ 销毁
          │           │           │           │
          │           │           └───────────┘
          │           └──→ 取消（有人退出 / 未满员）
          └──→ 解散（执事关闭 / 无人 10 分钟）
```

| 状态 | 允许的操作 |
| --- | --- |
| 等待 | 加入、离开、准备、改设置、转让执事、聊天 |
| 倒计时 | 取消、离开；不能改设置 |
| 对局中 | 指令、聊天、暂停投票、投降、离开 |
| 暂停 | 投票恢复、聊天、看面板；不能下指令 |
| 结算 | 查看分数、复制战报、返回大厅 |
| 销毁 | 无 |

### 房间寿命

- 等待状态最多 30 分钟；无人加入自动解散。
- 对局中全员离线 60 秒自动暂停。
- 暂停后 10 分钟无人回来，房间销毁。
- 结算后 2 分钟自动销毁。
- 服务器重启，全部销毁。

## 六、创建与加入

### 入口

主面板 →「时空」标签 →「加入时空」。

界面只有三行：

```
[创建时空]  成为执事，选择规则，生成时空码
[加入时空]  输入 4 位时空码
[公开时空]  浏览正在等待的房间
```

### 创建时空

1. 输入玩家名（最多 16 字符）。
2. 选择预设：快速局 / 标准局 / 朋友局 / 自定义。
3. 选择公开或私密。
4. 可选：4 位 PIN。
5. 点击创建。

服务器返回：

- 4 位时空码（去掉 0/O、1/I 等易混字符）。
- 初始执事标记。
- 房间设置。
- 当前成员列表。

时空码规则：

- 4 位，大写字母 + 数字。
- 排除 `0 O 1 I`。
- 大小写不敏感。
- 同一时间全局唯一。
- 私密房间不出现在公开列表。

### 加入时空

1. 输入时空码，或从公开列表点选。
2. 输入玩家名。
3. 如果房间有 PIN，输入 PIN。
4. 进入等待界面。
5. 所有人点击「准备」。
6. 执事点击「开始」。

### 等待界面

显示：

- 时空码（可一键复制）。
- 执事名字。
- 成员列表：名字、准备状态、延迟、执事标记。
- 房间设置摘要。
- 聊天 / 预设短语。
- 「申请执事」「转让执事」「离开」。

### 开始倒计时

- 执事点击开始后，3 秒倒计时。
- 所有人看到同一个倒计时。
- 倒计时期间不能加入。
- 倒计时结束，服务器生成随机种子，广播给所有成员。
- 所有客户端用同一份种子初始化 `GameState`。
- 第一个 tick 同时开始。

### 迟到加入

默认关闭。
快速局可以开启「迟到加入」：

- 只允许在前 30 分钟加入（快速局前 15 分钟）。
- 新玩家以平民开局，获得「追赶包」：资源 +50%，科技折扣。
- 或者以观战者身份加入。
- 标准局和长局默认不允许迟到加入。

## 七、执事机制

### 执事的权力

| 可以做 | 不可以做 |
| --- | --- |
| 发起开始倒计时 | 改别人的资源 |
| 发起暂停投票 | 改战斗结果 |
| 发起踢人投票 | 单方面改房间设置 |
| 转让执事 | 查看别人的完整状态 |
| 在等待阶段改设置 | 绕过规则 |

### 执事转让

- 等待阶段：任何成员可以点「申请执事」；当前执事同意即可转让。
- 也可以由当前执事直接选择一名成员转让。
- 对局中：执事可以转让，但只影响「会话协调」，不影响游戏。

### 执事掉线

- 服务器检测到执事心跳丢失 3 秒。
- 自动选举新执事：
  1. 优先选择状态哈希与多数人一致的成员。
  2. 延迟最低。
  3. 加入顺序最早。
- 新执事广播「执事变更」。
- 其他客户端更新执事标记。
- 原执事 5 分钟内回来，可以重新加入，但不自动夺回执事。

### 执事作弊

- 执事不能改别人的状态，因为所有客户端都跑同一套规则。
- 执事如果伪造自己的指令或状态哈希，客户端会检测到不一致。
- 执事不能篡改别人的消息，因为实际转发由服务器完成，执事只是会话协调人。
- 成员可以发起「不信任投票」；超过半数同意，执事被替换。
- 被替换的执事仍在房间里，但失去会话协调权。

### 踢人

- 等待阶段：执事可以直接踢人。
- 对局中：必须发起投票，超过半数同意才生效。
- 被踢玩家显示「你已被移出时空」。
- 被踢玩家 5 分钟内不能重新加入同一房间。

## 八、时间与帧同步

### 共享时钟

- 默认 tick = 2 Hz（每 0.5 秒一次）。
- UI 每秒刷新一次。
- 服务器每秒广播一次房间时钟：`tick`、`server_time`、`paused`。
- 客户端只接受当前 tick 窗口内的指令。
- 超出窗口的指令被服务器拒绝，防止加速外挂。

### 指令延迟

- 玩家点击操作后，指令进入本地队列。
- 指令在**当前 tick + 3** 执行（约 1.5 秒延迟）。
- 所有客户端在同一个 tick 执行同一批指令。
- 本地可以立即播放「已排队」的反馈，但结果以 tick 结算为准。

### 指令排序

同一 tick 内，指令按以下顺序执行：

1. tick 编号。
2. 玩家加入顺序（房间内固定索引）。
3. 玩家本地序列号 `seq`。
4. 指令类型优先级（资源 → 建造 → 科研 → 军事 → 外交）。

所有客户端使用同一套排序，保证结果一致。

### 暂停

- 任何成员可以发起暂停。
- 暂停需要超过半数同意（2 人房间需要双方同意）。
- 暂停期间服务器拒绝游戏指令。
- 暂停最长 10 分钟；超时自动恢复或销毁房间。
- 全员离线 60 秒自动暂停，不需要投票。

### 加速

- 默认 1x。
- 快速局可以 1.5x / 2x。
- 加速需要全员同意。
- 加速只改变 tick 间隔，不改变规则。

## 九、确定性模拟

### 为什么必须确定性

所有客户端都要算出一样的结果。
否则哈希对不上，或者更糟：每个人看到不同的战报。

### 确定性要求

| 要求 | 做法 |
| --- | --- |
| 固定 tick | 逻辑只按 tick 推进，不按 wall clock |
| 固定种子 | 服务器开局生成，所有人同一份 |
| 固定随机数 | 每个玩家 / 事件独立 RNG 流，按 tick + seq 取数 |
| 固定排序 | 指令按 tick → 玩家索引 → seq 排序 |
| 固定容器遍历 | 不用无序容器影响逻辑顺序 |
| 固定数值 | 统一使用 double / 定点数，避免平台差异 |
| 固定版本 | 所有客户端 rules_version 必须一致 |
| 无外部输入 | 逻辑层不读系统时间、不读网络、不读 UI |

### 版本校验

- 客户端启动时上报 `rules_version`。
- 加入房间时，服务器检查版本。
- 版本不一致，拒绝加入，提示「客户端版本不一致，请更新」。
- 对局中不允许热更新规则。

### 地图生成

- 服务器在开局时生成 `seed`。
- 所有客户端用 `seed` 生成同一张星区地图。
- 地图生成必须是确定性的：扇区数量、星球类型、资源、事件点全部由 seed 决定。
- 执事不能选 seed，也不能在开局后改 seed。

### 随机数

- 每个玩家有独立的 RNG 流：`room_seed + player_index`。
- 每个事件有独立的 RNG 流：`room_seed + event_id`。
- 战斗有独立的 RNG 流：`room_seed + tick + attacker + defender`。
- 这样某个玩家的 RNG 不会影响其他人。

### 全状态复制的代价

帧同步要求每个客户端都持有全房间状态。
这意味着：

- 每个客户端都知道所有人的资源、科技、舰队和殖民地。
- 技术上，修改客户端可以读到「全图」信息。
- 这不是状态篡改，而是信息优势，哈希互验抓不到。

本作的取舍：

- **休闲房间接受这个代价。** 朋友局里开全图挂的人，社交上会被发现。
- **排名/比赛使用公证模式 + 信息分层。** 客户端只拿到自己可见的详细状态，公证服务器持有全量状态。
- **UI 层仍然做战争迷雾。** 正常玩家看不到未探索扇区的细节。
- **不承诺防住所有信息类外挂。** 只承诺防住状态篡改和单方面改结果。

如果未来要做高强度竞技，需要把「全状态复制」改成「服务器权威 + 信息分层」。
那是另一套架构，不属于当前「客户端内存 + 帧同步」的范围。

## 十、状态哈希与共识

### 哈希什么

每 15 tick（约 7.5 秒），每个客户端计算一次状态哈希：

```
hash = FNV-1a-64(
    tick
  + 所有玩家的资源
  + 人口 / 士气
  + 建筑等级
  + 科技等级
  + 殖民地列表
  + 舰队编成
  + 扇区控制度
  + 事件队列
  + RNG 状态
)
```

序列化必须是确定性的：

- 字段顺序固定。
- 数字格式固定（例如统一保留 6 位小数）。
- 列表顺序固定。
- 不包含 UI 状态、不包含本地设置。

### 哈希交换

1. 每个客户端算出哈希。
2. 通过服务器转发给全房间。
3. 每个客户端统计多数值。
4. 如果自己的哈希与多数一致，继续。
5. 如果不一致，进入「失真处理」。

### 失真处理

```
发现不一致
  → 请求多数派提供最近一次共识快照
  → 回滚到快照
  → 重放快照之后的指令
  → 再次比对哈希
  → 一致：继续
  → 仍不一致：标记「失真」，进入观战
```

- 第一次失真：警告，自动重同步。
- 第二次失真：本局标记「可疑」，结算时显示。
- 第三次失真：移出对局，转为观战者。
- 被标记的玩家不能加入排名房间（如果以后有）。

### 多数派规则

- 3 人及以上：多数派哈希为准。
- 2 人房间：没有多数派，双方哈希不一致时：
  - 暂停，双方交换快照。
  - 比较指令日志，找出第一处分歧。
  - 无法解决则本局无效，不结算。
- 4 人及以上：如果出现 2v2，无法形成多数，进入「争议」状态：
  - 服务器只转发，不裁决。
  - 玩家可以投票结束本局，或继续（以执事所在阵营为准）。
  - 排名模式必须有公证，避免 2v2。

### 为什么房主不能单方面作弊

- 房主只负责会话协调，不负责转发别人的消息。
- 房主如果改自己的资源，他的哈希会和别人不一样。
- 房主如果伪造指令或哈希，客户端会发现不一致。
- 房主如果踢人，对局中需要投票。
- 房主如果掉线，自动迁移。

## 十一、反作弊威胁模型

| 威胁 | 例子 | 对策 | 能否根治 |
| --- | --- | --- | --- |
| 改存档 | 改本地文件加资源 | 联机不落盘 | 是 |
| 改内存 | 用工具改资源 | 状态哈希互验 | 大部分 |
| 改封包 | 伪造资源指令 | 全客户端规则校验 | 是 |
| 加速 | 提前执行指令 | 服务器 tick 窗口 | 是 |
| 房主作弊 | 单方面改战斗结果 | 客户端互验 + 执事迁移 | 大部分 |
| 合谋 | 两个作弊者互相包庇 | 公证模式（排名） | 排名可，休闲难 |
| 重放 | 重复发送旧指令 | tick + seq + 去重窗口 | 是 |
| 伪造房间 | 冒充官方服务器 | 服务器签名 / 固定地址 | 是 |
| 聊天注入 | 超长文本 / 控制字符 | 长度限制 + 转义 | 是 |
| 读内存看全图 | 修改客户端显示未探索信息 | 休闲接受；排名用公证 + 信息分层 | 排名可，休闲难 |
| 客户端改显示 | 只骗自己 | 不影响别人；信息类作弊见上一行 | 不需要 |

### 明确不承诺的事

- 不承诺「绝对无法作弊」。
- 不承诺「休闲房间能防住所有合谋」。
- 不承诺「修改客户端的人看不到假信息」。
- 不承诺「没有外挂」。

承诺的是：

- 作弊不能单方面改别人的游戏。
- 作弊会被多数客户端发现。
- 作弊者会被标记、移出、或只能骗自己。
- 排名模式有额外公证。

## 十二、数据生命周期

### 联机模式

| 数据 | 存在哪里 | 生命周期 | 是否落盘 |
| --- | --- | --- | --- |
| 房间元数据 | 服务器内存 | 房间销毁即消失 | 否 |
| 成员列表 | 服务器内存 | 房间销毁即消失 | 否 |
| 房间时钟 | 服务器内存 | 房间销毁即消失 | 否 |
| 游戏状态 | 每个客户端内存 | 离开 / 结束即消失 | 否 |
| 指令队列 | 客户端 + 服务器转发内存 | tick 执行后丢弃 | 否 |
| 状态哈希 | 客户端内存 | 比对后丢弃 | 否 |
| 聊天 | 客户端 + 服务器转发内存 | 滚动丢弃 | 否 |

- 所有房间消失。
- 所有客户端显示「时空已关闭」。
- 没有恢复，没有补偿。
- 这是设定，也是承诺。

### 隐私

- 没有账号，没有邮箱，没有手机号。
- 玩家 ID 是客户端随机生成的长字符串。
- 玩家名只存在房间内存里。
- 聊天不存档。
- 不做行为分析，不做广告画像。
- 服务器不记录 IP 到磁盘（内存日志最多 10 分钟）。

## 十三、掉线、重连、退出

### 掉线

- 服务器 3 秒内检测到心跳丢失。
- 玩家进入「离线托管」。
- 其他玩家看到「某某已离线，托管中」。
- 托管按玩家预设方针运行，效率 50%。
- 托管不主动攻击玩家，不建奇观，不发动战争。

### 重连

- 掉线后 5 分钟内可以重连。
- 使用同一个玩家 ID + 时空码。
- 服务器验证成员身份。
- 从执事或其他成员获取最新快照。
- 重放快照之后的指令。
- 哈希一致后恢复操作。
- 超过 5 分钟，视为放弃，转为观战或退出。

### 主动退出

- 等待阶段：直接退出，房间成员减一。
- 对局中：退出后进入托管，5 分钟内可重连。
- 结算前退出：保留结算分数，但显示「提前离开」。
- 执事退出：自动选举新执事。

### 投降

- 玩家可以在对局中投降。
- 投降需要二次确认。
- 投降后帝国变为中立，舰队解散，殖民地可被占领。
- 玩家转为观战者，保留结算分数。
- 不惩罚，不嘲讽，不弹「你确定吗」超过一次。

### 观战

- 观战者不占用玩家名额。
- 观战者可以看到全图，但不能发游戏指令。
- 观战者可以聊天（可被房主关闭）。
- 观战者延迟 10 秒，防止报点。
- 结算后观战者自动退出。

## 十五、社交与沟通

### 预设短语

不做自由文本输入（避免审核和骚扰），只做 6 条预设：

1. 「进攻这里。」
2. 「需要支援。」
3. 「别打我，谈。」
4. 「干得漂亮。」
5. 「你死定了。」
6. 「……」（沉默，表示无语）

### 快捷标记

- 在星区列表里标记一个扇区。
- 全房间看到一个小旗子。
- 不弹窗，不震动。

### 契约

- 玩家可以公开承诺：「我不打你，你也别打我。」
- 契约有持续时间。
- 撕毁契约会获得「失信」标记，全房间可见。
- 契约不是系统强制，只是社交约束。
- 系统会记录谁撕了约，但不阻止。

### 聊天

- 等待阶段可以自由文本（长度限制 200 字符）。
- 对局中只允许预设短语 + 快捷标记。
- 观战者聊天延迟 10 秒。
- 执事可以关闭聊天。
- 不做语音。

## 十七、失败场景与文案

| 场景 | 玩家看到 | 系统行为 |
| --- | --- | --- |
| 服务器连不上 | 「无法连接加入时空」 | 保留本地设置，允许重试 |

## 十八、公证模式（可选，排名用）

休闲房间不需要公证。
如果以后做排名/比赛，开启公证模式：

- 服务器在内存中跑一份**只读**的确定性模拟。
- 服务器不保存状态，只在内存中比对哈希。
- 服务器不参与转发以外的决策。
- 比赛结束，公证数据立即销毁。
- 公证结果只用于判定本局是否有效，不写入磁盘。
- 公证模式需要服务器和客户端同版本。
- 公证模式不防「服务器运营方作弊」，只防玩家作弊。

公证模式的价值：

- 解决 2 人房间没有多数派的问题。
- 解决 2v2 哈希平票的问题。
- 给排名/比赛一个可验证的结果。
- 仍然不落盘，符合「关房即焚」的承诺。

## 二十、落地路线

> **迁移原则**
>
> M0 保留服务端内存态，先保证现有客户端能玩；
> M1 客户端开始跑同一套模拟，服务端仍下发初始快照；
> M2 服务端只转发，不再保存 `GameState`；
> M3 才开启公证/排名。
> 每一步都可以独立发布，不要一次性推翻现有协议。

### M0：能连上

- 房间创建 / 加入 / 离开。
- 4 位时空码。
- 成员列表、准备、开始。
- 统一平民开局。
- 客户端内存状态，服务端不落盘。
- 现有 `/api/room/*` 端点。

### M1：能同步

- 共享 tick。
- 指令队列。
- 确定性模拟。
- 状态哈希。
- 失真检测与重同步。
- 服务器 tick 窗口。

### M2：能中断

- 托管。
- 重连。
- 执事迁移。
- 暂停投票。
- 全员离线暂停。
- 房间 TTL。

### M3：能竞技

- 公证模式。
- 观战延迟。
- 投票踢人。
- 结算战报（内存，不落盘）。
- 房间设置自定义。

### M4：能传播

- 公开房间列表。
- 预设短语。
- 契约系统。
- 地图种子分享（只分享种子，不分享存档）。
- 临时观战链接（房间码 + 观战位）。

## 附录：与现有客户端字段的兼容清单

现有客户端已经使用：

- `room`：时空码。
- `started`：`1` / `0`。
- `host`：当前玩家是否执事。
- `host_id`、`host_name`：执事信息。
- `member=id|name|score|fleet|colonies|capital|online|me`：成员行。
- `s=`：玩家状态串，逐行拼接后交给 `DeserializeState`。
- `battle=1`、`won`、`captured`、`loss`、`loot_minerals`、`loot_alloy`：战斗结果。
- 错误码：`no_room`、`started`、`not_started`、`not_host`、`room_full`、`bad_room`、`rejected`、`not_found`。

扩展时遵守：

1. 不删除旧字段。
2. 新字段只追加。
3. `member` 行前 8 段不变。
4. `s=` 行保持 `key=value` 格式。
5. 旧客户端遇到未知字段应忽略，不报错。
6. 服务端对未知 `action` 返回 `err=rejected`，不要崩溃。
